# NexusChat 设计目标

> 版本：v1.0
> 最后更新：2026-11-05

---

## 一句话

**局域网内，完全无中心，纯点对点的聊天工具。**

---

## 核心主张

| 主张 | 含义 |
|------|------|
| **零服务端** | 不存在任何服务器进程，不需要部署、不需要注册、不需要账号 |
| **零广播** | 不自动发现、不扫描局域网，好友关系完全由用户手动建立 |
| **数据本地** | 好友列表、聊天记录、文件缓存全部只在本地，不上传任何云端 |
| **隐私默认** | 不开端口不监听、不加好友不通信，每次连接都是双方主动行为 |

## 技术选型（已定）

| 分类 | 选型 | 备注 |
|------|------|------|
| **语言** | Java 25 | 虚拟线程、结构化并发、Pattern Matching |
| **UI** | JavaFX 25 (FXML + CSS) | 声明式界面 |
| **网络** | `java.net.Socket` + 虚拟线程 | 阻塞式 I/O，高并发无需 NIO |
| **协议帧** | 二进制帧（Magic + Type + Length + Payload） | 解决粘包 |
| **Payload** | JSON (UTF-8) | 易调试、易扩展 |
| **构建** | Maven | pom.xml 单文件，依赖管理清晰 |
| **存储** | SQLite (JDBC) | 单文件数据库，零配置 |
| **日志** | SLF4J + Logback | |

## 群聊架构（已定案）

> **群主 S = Server，成员 C = Client。群内所有消息经群主转发。**

```
                    ┌───────────┐
                    │ 群主 S     │ ← 创建者，唯一转发中枢
                    │ (Node A)   │
                    └──┬──┬──┬──┘
                       │  │  │   N-1 条 TCP 长连接
          ┌────────────┘  │  └────────────┐
          ▼               ▼               ▼
     ┌─────────┐    ┌─────────┐    ┌─────────┐
     │ 成员 C1 │    │ 成员 C2 │    │ 成员 C3 │
     └─────────┘    └─────────┘    └─────────┘
```

| 要点 | 说明 |
|------|------|
| 群主职责 | 维护成员列表、转发消息、处理入群/离群 |
| 消息流向 | 任何成员发消息 → 发给群主 → 群主广播全员 |
| 连接复用 | 成员到群主的 TCP 连接和单聊用同一个 `PeerConnection` 类 |
| ACK 语义 | 发送方只等群主 ACK，不被慢成员阻塞 |
| 群主离线 | **已定案**：剩余在线成员一致随机选新群主（各节点独立算、结果一致）；群聊结构永远保留，不降级单聊；剩 1 人自己当群主 + INACTIVE；**永不自动解散**，用户手动删除 |
| 代码开关 | `ChatService.isGroupLeader(groupId)` —— 一个判断决定走转发还是渲染 |

## 非目标（明确排除）

| 非目标 | 为什么不做 |
|--------|-----------|
| **自动发现/广播** | 违反隐私优先原则，手动 IP 添加就够 |
| **NAT 穿透 / 广域网** | 明确范围：仅同一局域网（同路由器内） |
| **多设备同步** | 本地存储，一个 deviceId 绑定一台设备 |
| **端到端加密** | **已定案排除**。局域网明文可信，不做 TLS。后续如有跨网段/公网需求再评估 |
| **多群主/分布式协调** | 复杂度爆炸，群主转发够用 |
| **离线消息存储** | 对方离线期间发的消息，不缓存、不重发（P2P 无法存储） |

## 边界条件

| 场景 | 预期行为 |
|------|---------|
| 两台机器在同一局域网，互相加好友 | ✅ 能发文字、图片、文件 |
| 一台机器有多个网卡（WiFi + 有线） | 启动时弹出网卡选择对话框 |
| Windows 防火墙拦截 | 首次连接时系统弹窗提示放行，或用户手动添加规则 |
| 群主在群聊天时关机 | 剩余成员一致随机选新群主（剩 1 人自己当群主 + 群 INACTIVE），群聊继续。群主回来作为普通成员重新加入，本地已收到的聊天记录完整保留 |
| 任何成员（包括群主）离线后重连 | 自动连接**当前群主**，恢复在线状态。**已收到的聊天记录因本地 SQLite 存储天然完整保留**。离线期间群里发的消息不补发（P2P 无服务器存储） |
| 传输中某成员离线 | 群主跳过离线成员，继续转发给在线的 |
| 文件传输中断（对方关机） | 临时文件保留在 temp/，不自动重传（需要用户手动触发） |
| 群聊会不会降级为单聊 | **永远不会**。不管剩 2 人还是 10 人，群聊就是群聊，结构永不降级 |
| 群聊会不会自动解散 | **永远不会**。只剩 1 人也保持在那里（INACTIVE 状态），只有用户手动删除才会消失 |

| Phase | 交付内容 | 功能编号 | 交付标准 |
|-------|---------|---------|---------|
| **Phase 1 骨架 + 单聊 MVP** | 项目骨架 + P2P 连接 + 帧编解码 + 好友添加 + 好友分组管理 + 文字聊天 + 心跳 | 1-9a | 两台机器能互相加好友、发消息、断线重连；好友可分组 |
